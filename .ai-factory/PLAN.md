Создан: 2026-07-15

## Настройки

- Тестирование: да — добавить регрессионные unit-тесты селектора ручных призов и выполнить целевые frontend-проверки.
- Логирование: стандартное — новые backend-логи не требуются; при ошибке загрузки сохранить существующий безопасный `console.error` страницы без персональных данных и без подавления ошибки.
- Документация: нет — API-контракт и Swagger уже содержат нужный защищённый endpoint, поэтому документационные изменения не нужны.

## Объём и решения

В админской карточке участника, ниже блока «Подобранные призы», показывать отдельный блок «Ручные призы» только при наличии подарков, назначенных этому участнику вручную. Автоматические и ручные назначения не объединять: первые остаются в `matched_gift_assignments`/`matched_gifts`, вторые загружаются через существующий защищённый admin API `GET /api/events/{eventId}/manual-gifts` и фильтруются по `recipient.id` текущего участника.

Новый backend endpoint, репозиторий, миграция и расширение публичного `ParticipantDetail` не нужны. Получатель остаётся доступен только в уже защищённой admin read model. По клику на ручной приз открывать существующую `MatchedGiftModal` с подписью «Назначен вручную».

## Задачи

### Этап 1: выборка и регрессия

- [x] Задача 1: Добавить чистый селектор `getManualGiftsForRecipient(manualGifts, participantId)` в `frontend/src/utils/manualGiftAssignment.ts` и покрыть его в `frontend/src/utils/manualGiftAssignment.test.ts`. Селектор должен вернуть в порядке ответа API только подарки с `manual_distribution=true` и `recipient.id`, равным ID участника, и исключить неназначенные подарки, подарки других участников и ошибочно попавший автоматический подарок. В `frontend/src/api/gifts.test.ts` добавить регрессионный тест готового клиента `giftsApi.getManualByEvent(eventId)`: он должен выполнить `GET /api/events/{eventId}/manual-gifts`. Логирование: не добавлять логи в чистую утилиту; тесты не должны содержать реальные персональные данные. Зависимости: нет.

### Этап 2: карточка участника

- [x] Задача 2: В `frontend/src/app/(dashboard)/participants/[id]/page.tsx` после получения участника загрузить существующий `giftsApi.getManualByEvent(participant.event_id)` параллельно с уже загружаемыми подарками и результатами, сохранить отфильтрованные через селектор ручные призы в локальном state и отрисовать отдельную карточку «Ручные призы» сразу под «Подобранные призы». При успешной пустой выборке карточку не показывать; для каждого приза отобразить описание, критерии при наличии и подпись «Назначен вручную», а клик должен открыть имеющуюся `MatchedGiftModal` по ID приза. Отделить ошибку protected enrichment-запроса от ошибок основных данных: очистить состояние ручных призов, сохранить данные участника, результата и автоматических призов, вывести на месте карточки сообщение «Не удалось загрузить ручные призы» и дать повторную загрузку при следующем открытии страницы. Не изменять `ParticipantDetail`, автоматические данные, публичные API и отображение «Призов от участника». Логирование: для ошибки ручного запроса использовать безопасный `console.error` с `participant_id`, `event_id`, операцией и ошибкой без описаний подарков, имён или usernames; новые backend-логи не добавлять. Зависимости: задача 1.
