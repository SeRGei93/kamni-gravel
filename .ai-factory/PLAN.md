# План реализации: поиск в лидерборде и каталоге призов Mini App

Ветка: main
Создан: 2026-07-14

## Настройки

- Тестирование: да
- Логирование: стандартное; новый runtime-лог для чистой клиентской фильтрации не добавлять, текст запроса и персональные данные не логировать
- Документация: нет — API, Swagger и публичные backend-контракты не меняются

## Объём и решения

Добавить одинаковое поисковое поле на экраны `/miniapp/leaderboard` и `/miniapp/gifts`, переиспользовав `frontend/src/utils/search.ts` из существующей логики админки. Поиск выполняется мгновенно на клиенте по уже загруженным полным наборам: новые query-параметры, backend-обработчики и запросы при вводе не нужны. Пустой или состоящий только из пробелов запрос считается неактивным и не должен менять таблицы, empty state или отображение пропущенных призовых мест.

В лидерборде поиск ограничен уже публичным полем `name`: не добавлять в Mini App Telegram ID, отдельный `username` или административные поля. Сначала рассчитывать места для выбранных фильтров пола и велосипеда, затем отбирать совпадения, чтобы найденный участник сохранял реальное место в текущем зачёте.

В каталоге искать по описанию приза, `username` и полному имени автора, сохраняя исходный порядок. Во время активного поиска не строить строки пропущенных призовых мест по сокращённому массиву, иначе скрытые совпадением призы будут ошибочно показаны как отсутствующие. Строка поиска живёт в соответствующем Mini App context и сохраняется при переходе в карточку и обратно, но не записывается в `sessionStorage`.

В `frontend/src/utils/search.ts` добавить общий `hasSearchQuery(query)`, который считает пустую и пробельную строку неактивной. Расширить `frontend/src/components/miniapp/MiniappLeaderboardContext.tsx` и `frontend/src/components/miniapp/MiniappCatalogContext.tsx` полями `searchQuery`/`setSearchQuery`, чтобы запрос сохранялся при открытии детальной карточки и возврате, но сбрасывался после полной перезагрузки Mini App. Не копировать admin debounce и URL-синхронизацию: ввод должен фильтровать уже загруженный список сразу и не запускать сеть. - [x] Задача 2: Подключить поисковое поле с плейсхолдером «Поиск по имени» и `aria-label="Поиск участника в лидерборде"` к `frontend/src/components/miniapp/LeaderboardFilters.tsx` и `frontend/src/app/(miniapp)/miniapp/leaderboard/page.tsx`. Сохранить навигацию в карточку и восстановление позиции списка. Логирование: новый runtime-лог для локальной фильтрации не добавлять; сохранить существующие WARN-сообщения только для ошибок загрузки, не записывая запрос или данные участника. Зависимости: задача 1.

Логирование: новый runtime-лог для локальной фильтрации не добавлять; сохранить существующие WARN-сообщения только для ошибок загрузки, не записывая описание, автора или запрос. Зависимости: задача 1.
