# Защита страницы награждения от устаревших ответов

**Дата:** 2026-07-15 22:07
**Файлы:** `frontend/src/app/(dashboard)/prize-distribution/page.tsx`, `frontend/src/utils/prizeDistribution.ts`, `frontend/src/utils/prizeDistribution.test.ts`, `frontend/src/components/prize-distribution/prizeDistributionColumns.tsx`
**Серьёзность:** medium

## Проблема

При смене активного события или размонтировании страницы незавершённый запрос
распределения мог сохранить loading-состояние либо поздним ответом затронуть
устаревший экран. В описании fallback отображался внутренний код причины.

## Корневая причина

Version guard проверял ответ, но эффект загрузки не инвалидировал запрос при
cleanup. Ветка без активного события очищала данные, но не всегда сбрасывала
`isLoading`. Причины fallback передавались из движка как технические коды без
presentation-слоя.

## Решение

Эффект загрузки теперь инвалидирует версию в cleanup, отсутствие или ошибка
активного события завершают loading, а сравнение версии вынесено в чистую
функцию с регрессионным тестом. Безопасные логи с префиксом
`[FIX:prize-distribution]` фиксируют инвалидацию и результат запроса. Коды
fallback преобразуются в понятные русские пояснения перед отображением.

## Предотвращение

- Для каждого async-запроса, который меняет React state, инвалидировать версию
  в cleanup эффекта.
- Тестировать отдельно сравнение старой и актуальной версий запроса.
- Не показывать пользователю технические коды API без presentation-слоя.
