# Patch: Reuse automatic prize distribution in My Gifts

## Problem

The Mini App My Gifts screen requested both `/api/miniapp/my-gifts` and
`/api/miniapp/participants`. Each endpoint calculated the automatic prize
distribution independently for the same event.

## Changes

- Extended the protected My Gifts response with privacy-safe participant
  options used by manual gift assignment.
- Reused one prize distribution result to build automatic gift recipients and
  participant `has_prize` flags.
- Removed the second participant-options request from the My Gifts page.
- Kept the separate participants endpoint intact for existing consumers.
- Added structured fix logs for the shared distribution calculation and its
  participant-options projection.

## Tests

- Added a query regression test proving recipients and participant options use
  one distribution call.
- Extended the Mini App handler test to verify the response and one call.
- Added a frontend page test proving My Gifts does not request participants a
  second time.

## Verification

- `cd backend && go test ./...`
- `cd backend && go test -race ./internal/application/query ./internal/infrastructure/http/handler`
- `cd backend && go vet ./...`
- `cd frontend && npm run test -- --run`
- `cd frontend && npx eslint 'src/app/(miniapp)/miniapp/my-gifts/page.tsx' 'src/app/(miniapp)/miniapp/my-gifts/page.test.tsx' src/types/index.ts`
- `cd frontend && npm run build`

## Rollback

Revert this patch to restore the separate `/api/miniapp/participants` request
from the My Gifts page.
